# Limit rollback to remaining datasets

Environment rollback restores contents in remaining datasets rather than reconstructing a historical dataset tree. Manual topology changes and their consequences are the user's responsibility; historical-tree reconstruction adds complexity with little benefit for the intended use cases. Leave any surviving child without the target snapshot untouched, whether added later or missing a manually deleted snapshot; ignore deleted children and roll back renamed children that retain it, while requiring the root's target snapshot and previewing affected and untouched datasets. The installation contract's refresh and validation requirement after external changes remains in force; see the [issue #6 interview](https://github.com/YoukouTenhouin/loka/issues/6).
